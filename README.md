# Прокат — учёт оборудования

Рабочее приложение на русском языке для небольшой компании по аренде оборудования. Приоритет — iPhone, также поддерживаются планшеты и компьютеры. Статические HTML/CSS/JavaScript, без сборки, платных сервисов и серверной установки.

Рабочий сайт: [leopold-butters.github.io/rental-equipment](https://leopold-butters.github.io/rental-equipment/). Исходный код: [GitHub](https://github.com/leopold-butters/rental-equipment).

## Запуск

Откройте `index.html` в браузере. Для стабильного хранения, установки на экран «Домой» и автономного режима используйте сайт по HTTPS или локальный HTTP-сервер:

```sh
cd rental-equipment
python3 -m http.server 8768 --bind 127.0.0.1
```

Откройте `http://127.0.0.1:8768`. На iPhone откройте опубликованный сайт в Safari, выберите «Поделиться», затем «На экран “Домой”». Значки, manifest, safe-area и нижняя навигация входят в поставку. После первого открытия по HTTPS приложение кешируется для работы без сети; данные при этом остаются в localStorage. Первый запуск требует подключения. Кеш обновляется из сети; после публикации обновления перезапустите приложение.

## GitHub Pages

Приложение опубликовано в репозитории `leopold-butters/rental-equipment`. Чтобы развернуть собственную копию:

1. Создайте отдельный репозиторий `rental-equipment` на GitHub.
2. Загрузите **содержимое** этой папки в корень репозитория: `index.html` должен находиться в корне.
3. Откройте Settings / Pages. Выберите Deploy from a branch, ветку `main`, папку `/ (root)`, сохраните.
4. После публикации откройте адрес сайта, указанный GitHub.

Все ссылки на ресурсы относительные, поэтому приложение работает и в подпапке Pages. Альтернатива: загрузить всю папку в корень другого репозитория и открывать `/rental-equipment/`.

## Ежедневная работа

- Добавьте оборудование: название, уникальный инвентарный номер, категорию, описание, фотографию, состояние, комментарий, четыре дневных тарифа.
- Добавьте клиента: имя или компанию, тип, телефон, email, реквизиты, комментарий и до трёх документов PDF/JPEG/PNG/WebP.
- Нажмите «Сдать в аренду», выберите клиента, дату выдачи и срок: 7/14/21/28 дней, свой срок или бессрочно. Можно учесть уже внесённую оплату.
- «Принять возврат» показывает фактические дни, диапазон, тариф и сумму. Укажите общую оплату или отметьте «Оплачено полностью».
- Неоплаченный остаток виден у клиента. «Карточка и история» показывает все аренды и позволяет учесть дополнительную оплату.
- Поиск и фильтры оборудования работают по названию, номеру, категории, клиенту, статусу и типу срока.
- В разделе «Цены» можно изменить тарифы. История фиксирует выдачи, возвраты, изменения, удаления и оплаты.
- Статистика содержит периоды, выручку, средний чек, количество аренд, рейтинг оборудования и клиентов, текущие просрочки.

Новая база пустая. Для знакомства в настройках есть **«Загрузить тестовый пример»**. Пример доступен только для пустой базы и требует подтверждения. Тестовые клиенты явно помечены. Пример не загружается автоматически.

## Расчёт дней и денег

Срок — разница календарных дат, минимум один день. Время суток не учитывается. Выдача 1 октября и возврат 11 октября — 10 дней. Выдача и возврат в один день — 1 день. При выдаче на 7 дней 1 октября срок возврата — 8 октября. Просрочка начинается 9 октября. Текущая дата берётся с устройства; его дата и часовой пояс должны быть корректными.

По умолчанию диапазоны: 1–7, 8–14, 15–21, 22+ дней. **Весь срок умножается на дневной тариф одного выбранного диапазона.** Для Sony FX3 с тарифами 4500/4000/3500/3000 ₽: 10 дней стоят 40 000 ₽, 25 дней — 75 000 ₽. Итог округляется до копеек.

Тарифы и границы сохраняются в аренде при выдаче. Изменение цен или настроек не меняет текущие и завершённые аренды. Настройки позволяют изменить три верхние границы; четвёртый диапазон автоматически начинается со следующего дня.

«Текущая стоимость» на главном экране — фактическая начисленная сумма активных аренд на сегодня. Оценка в форме срочной выдачи — сумма за выбранный срок. Итог всегда определяется фактической датой возврата. Бессрочная аренда не получает просрочку.

Выдачи в статистике относятся к дате начала, выручка и средняя стоимость — к дате закрытия. «Оплачено» — текущая общая оплата аренд, закрытых в выбранном периоде; это не отчёт движения денежных средств по дате оплаты. Текущие показатели оборудования и просрочки не зависят от периода. Количество всех аренд клиента включает активные; количество завершённых увеличивается после возврата. Задолженность показывает сумму неоплаченных начислений на сегодня, не юридическую дату наступления долга. Переплата одной аренды не погашает другие автоматически.

## Сохранение и резервные копии

При каждой операции база проверяется и целиком сохраняется в `localStorage` под ключом `rental-equipment.db`. Ошибка сохранения не меняет рабочую базу в памяти. При повреждении или неизвестной версии данные не перезаписываются; приложение предлагает восстановить копию.

Версия схемы — 2. `migrate()` сохраняет данные версии 1, добавляет границы тарифов, сумму оплаты и документы. Новая версия приложения должна добавлять миграцию, а не менять ключ или сбрасывать базу. Формат версии 1 относится к схеме этого приложения, не к произвольным сторонним файлам.

Открытые вкладки одного сайта получают обновления базы. Проверка ревизии предотвращает обычную перезапись устаревшей вкладкой. localStorage не является многопользовательской транзакционной базой; одновременное редактирование несколькими сотрудниками требует облачного хранилища.

**Настройки / Скачать полную копию JSON** сохраняют оборудование, фотографии, клиентов, документы, аренды, оплаты, историю и настройки. Восстановление JSON требует отдельного подтверждения и заменяет базу. Сначала сохраните текущую копию.

CSV UTF-8 с BOM, разделитель `;`, переносы CRLF, кавычки экранируются. Поля, похожие на формулы, получают защитный апостроф. Для Google Sheets при импорте выберите разделитель «точка с запятой». CSV подходит для анализа; для восстановления базы используйте JSON. При открытии в Excel телефон остаётся текстом благодаря защите ведущего `+`.

База привязана к браузеру и адресу сайта. Safari, другой браузер, другое устройство или смена домена могут иметь отдельные базы. Очистка данных сайта, приватный режим и ограничения браузера могут лишить доступа к базе. Регулярно сохраняйте JSON, особенно перед сменой адреса или устройства. Приложение не отправляет данные на сервер и не записывает CSV в GitHub.

Объём localStorage ограничен браузером. Фотографии сжимаются до 1200 px, JPEG качества 78%; документы ограничены 1 МБ каждый, максимум 3 на клиента. Если места недостаточно, сохранение покажет ошибку. Не используйте локальную базу как единственный архив клиентских документов. Авторизация, шифрование и разграничение доступа в базовой версии не предусмотрены.

Удаление оборудования и клиента запрещено при активной аренде. Любое удаление требует подтверждения. Закрытые аренды сохраняют названия и номера объектов даже после их удаления. Очистка журнала истории не удаляет архив аренд, задолженности или статистику.

## Облачное хранилище

Интерфейс и расчёты отделены от хранилища:

- `assets/domain.js`: правила дат, тарифов, состояний, статистики, миграции и валидации.
- `assets/repository.js`: фабрика репозитория, сейчас возвращает `LocalRepository`.
- `assets/app.js`: интерфейс; запись данных проходит через `mutate()`, восстановление через `restore()`.

Для подключения Supabase/Firebase сохраните структуру базы и замените фабрику репозитория. Текущий контракт: `db`, `error`, `commit(change)`, `restore(value)`. `commit` принимает чистую функцию изменения черновика, валидирует результат и обновляет `db` после успешного сохранения. Текущий контракт синхронный: для прямой серверной записи сделайте `mutate()` и вызывающие формы асинхронными, добавьте начальную загрузку и обработку конфликтов. Представления и правила расчёта остаются прежними. Альтернатива — локальный кеш с очередью синхронизации; очереди и конфликты нужно реализовать явно.

Облачная интеграция **не подключена**. Для неё потребуются проект базы, вход сотрудников, права доступа и версия записи на сервере. Нельзя помещать секретные ключи сервера в публичный сайт. В Pages допустим только публичный клиентский ключ с серверными правилами доступа. Пользовательские документы желательно хранить в защищённом файловом хранилище.

## Проверки

Бизнес-правила проверяются без зависимостей:

```sh
node --test tests/domain.test.cjs
```

Браузерные сценарии требуют установленный Playwright, Edge либо Chromium и WebKit:

```sh
TEST_URL=http://127.0.0.1:8768 TEST_BROWSER_CHANNEL=msedge node tests/browser.test.cjs
```

При нестандартной установке задайте `PLAYWRIGHT_MODULE` абсолютным путём пакета, а для временно установленных движков — `PLAYWRIGHT_BROWSERS_PATH`. `TEST_BROWSER_CHANNEL` задаёт канал Chromium, по умолчанию `msedge`. Скриншоты тестов записываются в `tests/artifacts/` и не являются данными приложения.

Поставка не требует Node, Python или Playwright для работы сайта — это инструменты разработки и проверки.
